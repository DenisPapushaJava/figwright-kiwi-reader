# Figwright Kiwi Reader

Браузерный read-only адаптер Figwright для чтения макетов Figma без Figma-плагина, REST-токена,
OAuth и лимитов REST API. Расширение Chrome получает только входящие бинарные WebSocket-кадры уже
открытого пользователем файла, а локальный MCP-сервер декодирует Kiwi scenegraph и отдаёт выбранный
узел агенту разработки.

Проект основан на открытом [Figwright](https://github.com/awdr74100/figwright) и сохраняет исходную
MIT-лицензию. Обычный двунаправленный Figwright остаётся в репозитории; Kiwi Reader является
отдельным провайдером чтения и не меняет макет.

## Возможности

- работа с Figma Design непосредственно в Chrome;
- чтение выбранного фрейма или узла из Figma URL;
- геометрия, auto-layout, тексты, заливки, эффекты и структура потомков;
- несколько открытых файлов и вкладок;
- один локальный MCP-хаб для одновременной работы Codex, Cursor, Claude и других клиентов;
- сопоставление экземпляров, иконок и фактических цветов Figma с компонентами, SVG, CSS/SCSS-
  токенами и статически читаемыми темами Tailwind/UnoCSS существующего UI-kit проекта;
- ограничение глубины, количества узлов и размера ответа;
- section plan для последовательного чтения больших экранов;
- постоянная боковая панель Chrome с прогрессом и диагностикой;
- вызов из любого нового диалога Codex через `@fk`;
- отсутствие команд изменения Figma.

Kiwi — внутренний и недокументированный протокол Figma. Его формат может измениться. Reader получает
схему из текущей браузерной сессии и возвращает понятную ошибку совместимости, но бессрочная
совместимость не гарантируется.

## Быстрый запуск из исходников

Требуются Node.js 24, pnpm 12, Chrome 116+ и Codex.

```powershell
git clone https://github.com/DenisPapushaJava/figwright-kiwi-reader.git
Set-Location figwright-kiwi-reader
corepack pnpm install --frozen-lockfile
corepack pnpm build
```

Для ручной проверки запустите MCP-сервер:

```powershell
node .\packages\kiwi-reader\dist\mcp.mjs
```

Загрузите `packages\kiwi-reader\extension` через `chrome://extensions` → **Режим разработчика** →
**Загрузить распакованное расширение**. Откройте Figma, выделите фрейм, нажмите значок расширения и
выберите **Подключить макет**.

### Общий хаб для нескольких MCP-клиентов

Обычный `mcp.mjs` подходит одному клиенту и сохраняется для совместимости. Если к одному браузерному
захвату должны одновременно обращаться разные IDE или агенты, запустите один общий процесс:

```powershell
$env:FIGWRIGHT_KIWI_HUB_TOKEN = '<случайный секрет длиной не менее 32 символов>'
node .\packages\kiwi-reader\dist\hub.mjs
```

В MCP-клиентах укажите Streamable HTTP URL `http://127.0.0.1:9225/mcp` и заголовок
`Authorization: Bearer <тот же секрет>`. Состояние процесса доступно по
`http://127.0.0.1:9225/health`. Порты можно изменить переменными `FIGWRIGHT_KIWI_PORT` и
`FIGWRIGHT_KIWI_HUB_PORT`.

Хаб не хранит общий «активный файл»: после `list_files` агент передаёт `fileKey` или `tabId` в каждый
запрос, если открыто несколько вкладок. Поэтому один клиент не может незаметно переключить макет у
другого. Без `FIGWRIGHT_KIWI_HUB_TOKEN` хаб всё равно доступен только через loopback и выводит
предупреждение; для обычной работы токен рекомендуется.

## Установка готового релиза

1. Скачайте `figwright-kiwi-reader-vX.Y.Z.zip` из GitHub Releases.
2. Распакуйте архив в постоянную папку.
3. Запустите `install.ps1` в PowerShell.
4. Откройте `chrome://extensions`, включите режим разработчика и загрузите распакованное расширение
   из пути, который напечатал установщик.
5. Перезапустите Codex.

После этого в новом диалоге доступны команды:

```text
@fk проверь подключение к Figma
@fk прочитай выбранный фрейм
@fk получи полный design context выбранного фрейма
@fk прочитай узел https://www.figma.com/design/...?node-id=...
@fk подготовь выбранный фрейм к реализации в текущем проекте
```

Установщик размещает сервер и расширение в `%LOCALAPPDATA%\FigwrightKiwi`, запускает один общий
локальный hub, создаёт персональный Codex-плагин `fk` и регистрирует его в локальном marketplace.
Каждый диалог Codex подключается к этому hub через лёгкий stdio-адаптер, поэтому несколько задач не
конфликтуют за порт захвата и не дублируют дерево Figma в памяти. Если hub завершился, следующий
диалог Codex запустит его снова. Глобальная Git-конфигурация и другие проекты не изменяются. При
обновлении повторно запустите `install.ps1` из нового релиза и нажмите **Обновить** у расширения на
странице `chrome://extensions`.

При реализации в существующем проекте агент вызывает `get_implementation_context` с абсолютным
`rootDir` этого проекта. Один ограниченный по размеру ответ содержит дерево макета, инвентарь
ресурсов, профиль стека и результаты `component_map`, `icon_map` и `token_map`. Если дерево было
ограничено по глубине или числу узлов либо общий ответ слишком велик, инструмент возвращает
`sectionPlan`: агент повторяет тот же вызов для перечисленных секций, не пытаясь уместить весь экран
в один ответ. Для такого планирующего ответа нормализация полного дерева и сканирование проекта не
запускаются; поля из `deferred` появятся в ответах отдельных секций. Отдельные map-инструменты
остаются для точечной проверки.

Лимит MCP-ответа считается по фактическому размеру UTF-8, поэтому кириллица и другие многобайтовые
строки не обходят ограничение. Перед полной нормализацией Reader считает безопасную нижнюю границу
размера по обязательным полям каждого узла. Если уже она превышает лимит, сразу возвращается
`sectionPlan`; в остальных случаях окончательное решение по-прежнему принимает точный размер
сериализованного ответа. Повторное чтение того же узла использует ограниченный LRU-кэш
нормализованного дерева. Для каждой записи сохраняются зависимости от дочерних узлов, родителей и
мастер-компонентов, поэтому обновление другой ветки scenegraph не сбрасывает полезный кэш. Изменение
зависимости инвалидирует только затронутую запись; если ограниченной истории изменений уже
недостаточно для точного решения, Reader безопасно пересобирает её.

`token_map` читает реально использованные цвета заливок, обводок, градиентов, теней и смешанного
текста и ищет точное совпадение в CSS custom properties и SCSS variables.
Совпадение помечается `matchedBy: ["value"]` и уровнем `medium`: это кандидат на повторное
использование, а не доказанная привязка переменной Figma. Одинаковые по значению токены остаются
неоднозначными. Kiwi отдаёт стабильные id общих стилей, но пока не раскрывает их названия и
определения, поэтому Reader возвращает такие ссылки отдельно и не придумывает семантику. JS/TS-
конфиги токенов переносимый сканер не исполняет.

## Сборка переносимого комплекта

```powershell
corepack pnpm build
corepack pnpm package:kiwi
```

Готовая папка появится в `artifacts\figwright-kiwi-reader`. Сервер собирается вместе с runtime-
зависимостями, поэтому на другом ПК для запуска нужен Node.js 24, но не нужны pnpm и `node_modules`.

## Работа с изменениями

Каждая отдельная функция, ошибка или правка документации выполняется в собственной ветке и
попадает в `main` только через Pull Request:

```powershell
git switch main
git pull --ff-only origin main
git switch -c feat/short-name # либо fix/..., docs/...
# внести изменения и выполнить проверки
git push -u origin HEAD
```

Один PR должен решать одну логическую задачу. Заголовок PR оформляется как Conventional Commit,
например `fix(tools): recapture raster bodies without browser cache`. После успешного CI используется
**Squash and merge**. Прямые коммиты и push в `main` для обычной разработки запрещены; исключение —
только документированный release-коммит, создаваемый `pnpm release`. Заголовок остаётся на
английском для changelog и автоматики, а описание задачи, изменения, проверки и заметки ревьюеру
пишутся на русском.

## Релизный цикл

Kiwi Reader выпускается независимо от основного Figwright:

1. Откройте **Actions → Prepare Kiwi Reader Release → Run workflow**.
2. Выберите тип повышения версии: `patch`, `minor` или `major`.
3. Workflow синхронно обновит версии расширения и Codex-плагина, создаст ветку
   `release/kiwi-vX.Y.Z` и откроет черновик PR с русским описанием.
4. Проверьте версию и нажмите **Ready for review**. Это действие от вашего имени запустит
   обязательные PR-проверки, которые GitHub связывает с release-PR.
5. После успешного CI выполните **Squash and merge**. Изменение версии в `main` автоматически
   запустит `Kiwi Reader Release`.

Release workflow повторно выполняет все проверки, создаёт тег `kiwi-vX.Y.Z`, ZIP и SHA-256
checksum, после чего публикует GitHub Release. Обычный merge без изменения двух файлов версии релиз
не запускает.

Перед merge релизного PR при необходимости соберите комплект локально и проверьте его на чистом
Windows-профиле:

```powershell
corepack pnpm build
corepack pnpm test
corepack pnpm package:kiwi
```

Ручной тег `kiwi-vX.Y.Z`, совпадающий с версиями в обоих manifest, остаётся резервным способом
перезапуска release workflow. Теги `kiwi-v*` отделены от upstream-тегов `v*`, чтобы случайно не
запустить публикацию оригинального `@figwright/mcp` в npm.

## Безопасность и границы

- Передаются только server-to-browser WebSocket-фреймы; исходящие команды не пересылаются.
- Cookies и токены Figma не читаются и не сохраняются.
- Локальный сервер слушает только `127.0.0.1` и принимает соединение доверенного расширения.
- Диагностика не содержит содержимое макета и сырые сетевые кадры.
- Размер одного кадра, очереди, scenegraph и MCP-ответа ограничен.
- В Reader отсутствуют encode, replay и инструменты изменения Figma.
